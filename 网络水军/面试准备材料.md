# 网络水军检测项目 — 完整面试准备材料

---

## 一、30 秒项目概述

> 我做了一个电商评论水军自动检测系统。数据有 6:1 的类别不平衡，手工特征 F1 只有 0.53。核心突破是引入 BERT 提取评论语义向量（384 维），与手工特征和图网络特征融合形成 410 维特征，配合 SMOTE 处理不平衡和 XGBoost 集成，最终 F1 达到 0.84，AUC 达到 0.976。完整覆盖了特征工程、无监督探索、图网络、集成学习、SHAP/LIME 可解释性 5 个环节。

## 二、2 分钟完整项目介绍

### 项目背景

电商平台水军评论泛滥。水军通过批量发布虚假好评或恶意差评来操纵商品口碑。我需要设计一个自动检测系统，从 12000 条标注数据中学习如何区分水军和正常用户。

### 数据概况

数据字段包括用户名称、级别、评价星级、评价内容、标注（水军/正常）、时间。标签分布约 6:1 不平衡（正常约 10000，水军约 2000）。

### 技术路线（8 步 Pipeline）

整个项目遵循"探索 → 建模 → 突破 → 解释"的研究思路：

**Step 1 — 特征工程**：从四个维度设计 20 个手工特征。文本统计维度（字数、词汇丰富度、感叹号数量等 10 个），用户行为维度（发评频率、平均评分、评分方差、平均发评间隔等 4 个），时间维度（发帖小时、星期几、是否周末、是否深夜等 4 个），评分维度（评分值、是否极端评分等 2 个）。每个特征背后都有水军行为假设——比如水军倾向在深夜批量发帖（is_night 后来被 SHAP 验证为 Top 1 特征），水军发帖频率异常高，水军倾向打极端评分。

**Step 2 — 无监督探索**：用 Isolation Forest、DBSCAN、LOF 三种无监督异常检测方法，投票机制判定（≥2/3 同意才算异常）。F1 只有 0.11——证明水军和正常用户在特征空间高度重叠，简单方法无效。这一步的意义是建立 baseline、证明问题难度、形成完整探索叙事。

**Step 3 — 图网络分析**：将用户构建成相似度网络。用 TF-IDF + 余弦相似度，相似度 > 0.75 则连边。采样 5000 个节点避免 O(N²) 内存爆炸。用 Louvain 算法做社区检测（发现 3 个社区），用 PageRank 找核心节点，计算度/介数/接近/特征向量四种中心性。三把筛子（高 PageRank top10% + 高度数 > μ+2σ + 大社区成员 > 10 人）用"或"逻辑筛选可疑名单。

**Step 4 — 集成学习**：用 SMOTE+Tomek Links 将水军过采样到平衡状态。训练 XGBoost、LightGBM、CatBoost、RandomForest 四个异构模型。Voting Ensemble 用软投票 + weights=[2,1,1] 组合三个 GBDT。Stacking Ensemble 用 5 折 CV 生成干净预测，LogisticRegression 做元学习器学权重。每个模型单独做阈值优化（grid search 0.3~0.7 找 F1 最优阈值）。F1 从 0.11 提升到 0.58。

**Step 5 — 可解释性**：用 SHAP 做全局分析（Bar Plot 排名 + Beeswarm 分布 + Waterfall 单样本），用 LIME 做局部近似解释。生成包含风险等级（高/中/低/正常）的综合检测报告。发现 is_night 是 Top 1 特征，验证了时间维度假设。

**Step 6 — BERT 语义增强（关键突破）**：用 Sentence-Transformers 的 paraphrase-multilingual-MiniLM-L12-v2 模型，把每条评论编码为 384 维语义向量。与 20 维手工特征融合为 404 维。用 ADASYN（按难度分配采样）替代 SMOTE。控制实验：仅 20 维 → F1=0.58，20+384 维 → F1=0.84。Recall 从 0.53→0.86，说明大量之前漏掉的水军被发现。

**Step 7 — GNN 图特征融合**：提取 6 维图网络特征（度、聚类系数、PageRank、介数中心性、接近中心性、特征向量中心性），与 404 维融合为 410 维。F1 基本持平（0.84），但 AUC 从 0.96→0.976，模型排序能力显著增强。

**Step 8 — 最终报告**：生成性能汇总表、演进趋势图、特征重要性分析。

### 最终成果

- 最佳 F1：**0.8425**（BERT 增强，相对基线提升 60%）
- 最佳 AUC：**0.9759**（BERT + GNN 融合）
- 证明了水军的核心区分信号在语义层面而非表面统计

## 四、高频追问 — 特征工程

### Q1：为什么选择这 20 个特征？设计思路是什么？

水军的行为模式和真实用户有系统性差异，我从四个可能暴露这种差异的维度设计了特征：

**文本统计（10个）**：水军倾向批量发布短评论文本、用模板，所以关注字数（text_length）、词数（word_count）、词汇丰富度（vocabulary_richness）、感叹号数量（exclamation_count）、问号数量（question_count）、特殊字符比例（special_char_ratio）、数字比例（digit_ratio）、平均词长（avg_word_length）、重复字符比例（repeated_char_ratio）、唯一词比例（unique_word_count）。

**用户行为（4个）**：水军账号存在的唯一目的就是发评论，所以行为模式异常。comment_frequency（发评频率，水军一天几十条）、average_rating（平均评分，水军全 5 星或全 1 星）、rating_std（评分标准差，水军评分模式单一→标准差低）、avg_time_interval（平均发评间隔，水军批量操作→间隔极短且均匀）。

**时间（4个）**：水军脚本常在夜间批量运行。hour（发帖小时）、day_of_week（星期几）、is_weekend（是否周末）、is_night（是否深夜，0 点至 6 点）。is_night 后来被 SHAP 验证为最重要的特征。

**评分（2个）**：rating（评分值本身）、is_extreme（是否极端评分，1 星或 5 星）。水军倾向打极端分来最大程度影响商品口碑。

主要使用 jieba 分词做中文处理，配合自定义停用词表过滤无效词。

### Q2：is_night 为什么这么重要？

真实用户在深夜（0-6点）发商品评论的概率极低——正常人要么在睡觉，要么在做其他事情。而水军的批量发布脚本经常在服务器低负载的深夜时段自动运行。这个特征在 SHAP 全局分析中排名第一，验证了"水军行为在时间维度异常"的初始假设。

### Q3：特征工程有没有考虑过做特征交叉？

在 Step 1 中没有做显式的特征交叉，原因有两个：① 20 个手工特征已经是领域知识驱动的，每个都有明确的物理含义，交叉后反而难以解释；② 后续的 GBDT 模型天然具备特征交叉能力——树的每一层切分 + 下一层在不同子集上继续切分，本质上就是在隐式学习特征交叉。如果你做了 is_night × text_length 的交叉特征，GBDT 通过树结构也能学到"深夜 + 短文本 = 水军"这种组合模式。

### Q4：为什么用 jieba 而不是其他分词工具？

jieba 是中文分词领域最成熟的工具之一，支持精确模式、全模式和搜索引擎模式。在这个场景中，评论是短文本，精确模式够用。配合自定义停用词表（过滤"的""了""是"等无意义词），分出来的词质量足够支撑后续的 TF-IDF 和文本统计特征。

## 五、高频追问 — 无监督学习

### Q1：无监督 F1 只有 0.11，为什么还花时间做这步？

三个层面的原因：

**叙事层面**：从 0.11 到 0.84 是一个完整的故事弧线——证明问题难 → 上模型突破 → 语义增强飞跃。没有 0.11 的失败，就没有 0.84 的说服力。

**工程层面**：建立 baseline 是 ML 项目的标准流程。后续每一项优化（SMOTE、集成、BERT、GNN）都有明确的参照点，提升幅度可量化。

**探索层面**：无监督方法尝试了三种不同假设（IF 假设异常点容易被孤立、DBSCAN 假设水军形成密集簇、LOF 假设水军和邻居密度差异大），发现没有一个假设完美匹配水军检测场景——这个结论本身就有价值，为后续选择有监督方法提供了依据。

### Q2：三个无监督方法各自为什么失败？

**Isolation Forest**：假设异常点是少数的、容易被随机切割孤立。contamination 参数需要预设异常比例，但 6:1 的比例和"水军是少数"不完全匹配——正常用户中也有看起来"异常"的（比如一个特别活跃的真实用户）。而且 IF 只用了一个假设（异常点更容易被孤立），在 20 维稀疏特征空间中，这个假设不够强。

**DBSCAN**：基于密度聚类。两个关键参数——eps（邻域半径）和 min_samples（最小邻居数）。调到 eps=0.8 是从 0.5 逐步上调的，因为 20 维空间中样本普遍距离较远，eps 太小 → 大部分样本被当成噪声。但 eps 太大 → 水军和正常被聚到一起。本质问题是：水军在 20 维手工特征空间中并不必然形成密集簇。

**LOF**：局部异常因子，比较每个样本和它周围邻居的密度。如果一个水军周围的 K 个邻居也都是水军，LOF 会认为他"密度正常"而放过他。LOF 依赖局部邻域的密度差异，但水军可能群体行动，在局部区域反而是密集的。

**投票机制**（≥2/3 判定异常）：进一步降低了召回率——三个方法都倾向于漏检不同类型的水军，投票是"交集"逻辑，漏得更多。

### Q3：contamination 参数是什么？设了多少？

contamination 是 Isolation Forest 中预设数据集中异常点比例的阈值参数。它不参与模型训练，只影响最后的 score 阈值——模型对所有样本打分后，取分数最低的 contamination% 判为异常。项目中设为 0.15（约等于水军比例），但实际水军比例约 0.14。问题是这个参数假设你知道真正的异常比例，而现实中往往不知道。而且 6:1 的不平衡在这里被"拉平"成 1:1 的效果了——污染比例设多少？设低了漏，设高了冤。

## 六、高频追问 — 图网络分析

### Q1：图是怎么建的？节点和边各代表什么？

**节点**：每个用户（评论）是一个节点。采样 5000 个是因为相似度矩阵是 O(N²) 空间——所有节点两两算相似度。5000×5000 的矩阵约 100MB，可接受。全量 12000×12000 约 600MB，内存不够。

**边**：两个用户评论的 TF-IDF 向量的余弦相似度 > 0.75 → 连一条无向边。这意味着两人的评论内容高度相似——可能是同一个模板。

**过程**：所有评论文本 → jieba 分词 → TF-IDF（max_features=100）→ 5000×100 矩阵 → cosine_similarity → 5000×5000 相似度矩阵 → 阈值 0.75 截断 → NetworkX 图。

### Q2：Louvain 社区检测是怎么工作的？

核心指标是**模块度（Modularity）**——衡量社区划分质量。公式：

```
Q = (社区内部边数/总边数) - (随机网络中该社区内部边数的期望/总边数)

Q 越高 → 社区内部连接比随机情况更密集 → 社区划分越好
Q 范围约 [-0.5, 1]，通常 Q > 0.3 就说明有较明显的社区结构
```

算法分两步迭代：

**第一步（局部优化）**：每个节点依次尝试移动到邻居所在的社区，如果移动后模块度提升，就搬家。重复多轮直到所有节点都不再移动。

**第二步（网络收缩）**：把一个社区的所有节点合并成一个"超节点"。社区内部的边变成超节点的自环。社区之间的边合并为超节点之间的加权边。

然后对这个收缩后的新网络，回到第一步继续。直到模块度不再增加。

### Q3：PageRank 在无向图中是什么意思？alpha=0.85 是做什么的？

原版 PageRank 是 Google 的网页排名算法——被重要网页链接的网页 → 也重要。在无向图中，关系变为"互相关注"，PageRank 等价于"邻居重要 → 你也重要"。

公式：PR(u) = (1-α)/N + α × Σ(PR(v) / degree(v))，v 是 u 的所有邻居。

**alpha=0.85** 是阻尼系数，物理含义是"用户有 85% 的概率沿着链接继续浏览，15% 的概率随机跳转到任意页面"。在数学上，alpha 确保 PageRank 方程有唯一解且迭代收敛。alpha 越接近 1 → 越依赖图结构，收敛越慢。0.85 是经典经验值。

### Q4：三个中心性指标的区别？为什么 Step 3 没直接用？

- **度中心性**：你有多少邻居。水军 → 和很多人内容相似 → 度高
- **接近中心性**：你到所有其他节点的平均距离。水军核心节点 → 到所有人的距离都短
- **介数中心性**：有多少对节点的最短路径经过你。水军"桥梁"节点 → 连接不同团伙

Step 3 中没有直接使用这些中心性做判定，而是用了一套启发式规则（三把筛子：高 PageRank top10% + 高度数 > μ+2σ + 大社区成员 > 10 人，"或"逻辑）。中心性指标被保留下来，在 Step 7 中作为 6 维图特征输入 GBDT 模型，让模型自动学习它们的最佳组合方式。

### Q5：为什么采样 5000 而不是全量？

相似度矩阵计算是 O(N²)：全量 12000 → 12000×12000 = 1.44 亿个浮点数 → 约 1.1 GB，再加上中间计算过程 → 内存不够。采样 5000 → 25M 个值 → 约 200 MB，可以接受。

采样的代价是丢掉了一些用户之间的关系。缓解措施：随机采样（不是取前 5000 个），确保分布不偏。

## 七、高频追问 — SMOTE 和类别不平衡

### Q1：6:1 为什么不是极端不平衡？到什么程度才算极端？

这个判断基于两个维度：

**绝对数量**：水军有约 2000 条。这 2000 条不是 20 条——SMOTE 有足够的"原材料"来合成。如果水军只有 50 条，SMOTE 在 20 维空间中几乎就是在那 50 个点之间拉直线，没多少变化。

**相对比例**：6:1 意味着水军占比约 14%。在风控场景中，这种比例很常见。真正极端的是 100:1 甚至 1000:1——比如信用卡欺诈，99.9% 的交易都是正常的。那种情况需要更激进的方法（One-Class SVM、异常检测为主）。

6:1 恰好是一个"有处理价值但不算极端"的区间——SMOTE 过采样 + class_weight 就够用，不需要上代价敏感学习或 Focal Loss 等重武器。

### Q2：SMOTE 为什么不是随机复制？插值具体怎么做的？

随机复制 = copy-paste。模型看到一模一样的样本 → 训练时这部分没有新的信息量 → 等于没做。

SMOTE 的插值过程：

```
选一个水军样本 x，找它的 K 个最近邻（也是水军）
随机选其中一个邻居 x_nn
在 x 和 x_nn 的连线上随机取一个点：
  x_new = x + λ × (x_nn - x)，λ ~ Uniform(0, 1)

举例（只看 3 个特征）：
  x     = [text_length=20, is_night=1, hour=3]
  x_nn  = [text_length=14, is_night=1, hour=5]
  λ = 0.4
  x_new = [20+0.4×(14-20), 1+0.4×(1-1), 3+0.4×(5-3)]
        = [17.6, 1, 3.8]
  
  新样本在两者之间的某处，既保留了水军的整体模式，又是新的组合。
```

**为什么有效**：SMOTE 不是在两个点之外乱造（那会超出合理范围），而是在已知的水军样本之间"填充"——相当于增加了水军类的"密度"。决策边界因此变得更平滑、更丰富。

### Q3：Tomek Links 是什么？为什么 SMOTE 后还要清理？

Tomek Links 是两个不同类别的样本对，它们互为最近邻：

```
样本 A（水军）和样本 B（正常）互为最近邻 → 构成一对 Tomek Link
→ A 和 B 贴得太近了，处在分类边界的"模糊地带"
```

Tomek Links 的做法是删除这对中的**多数类样本**（正常），因为多数类有冗余。删除后 → 边界更清晰，两类之间拉开了一段距离。

SMOTETomek = SMOTE（合成少数类，往边界推）+ Tomek Links（删除边界的多数类，把边界往回拉）。两者配合：SMOTE 让边界向多数类扩展，Tomek Links 清理掉那些被推到"骑墙位置"的多数类样本。

### Q4：ADASYN 和 SMOTE 的数学区别？

SMOTE：对每个少数类样本，合成同样数量的新样本。

ADASYN：先对每个少数类样本 i，数它 K 个邻居中有多少是多数类，计算比例 r_i。然后：

```
权重 w_i = r_i / Σr_j
合成数量 n_i = w_i × 总合成数
```

r_i 高（被多数类包围得多）→ w_i 大 → 合成得多。按难度分配合成预算。

在 20 维空间中，样本难度差异不大（手工特征区分度有限）→ SMOTE 和 ADASYN 效果接近。在 404 维空间中，BERT 特征把难度差异拉大了 → ADASYN 明显优于 SMOTE。

### Q5：为什么 sampling_strategy=0.8 不是 1.0？

0.8 表示合成后少数类（水军）样本数 = 多数类（正常）的 80%，而不是 100%。

1.0 虽然让两类完全平衡，但有两个问题：① 可能让模型过度关注水军，Precision 下降（宁可错杀）；② 现实中水军确实是少数，完全拉平丧失了"先验信息"的微弱信号。

0.8:1 是一个经验折中——极大改善了 6:1 的失衡，同时保留了微弱的多数类偏向，让模型在 Precision 和 Recall 之间取得更好的平衡。这个值可以通过交叉验证微调。

### Q6：class_weight='balanced' 怎么算的？

sklearn 中 class_weight='balanced' 自动计算：

```
class_weight[k] = n_samples / (n_classes × n_samples_of_class_k)

正常：12000 / (2 × 10000) = 0.6
水军：12000 / (2 × 2000)  = 3.0
```

水军的错判代价是正常的 5 倍。加在损失函数里：判错一个水军，损失 × 3.0。模型不敢随便判水军为正常。

XGBoost 用 scale_pos_weight 表示同样的事：

```
scale_pos_weight = sum(正常) / sum(水军) = 10000/2000 = 5（或 6，四舍五入）
```

SMOTE 后两类接近 1:1 了 → class_weight 接近 1:1 → 权重的作用被 SMOTE 覆盖。保留它是双保险。

## 八、高频追问 — 集成学习（GBDT 家族）

### Q1：GBDT 的核心思想？和 AdaBoost 的本质区别？

AdaBoost：改**权重**。错分的样本 → 下一轮权重增大 → 模型更关注难样本。

GBDT：改**目标**。不是预测原始标签（0/1），而是预测上一轮的**残差**（预测值和真实值的差距）。

```
AdaBoost：第 t 轮关注"之前判错的人"
GBDT：第 t 轮学习"之前还剩多少没预测到"

AdaBoost 是"把这题做对"→ 增大错题权重
GBDT 是"把差距补上"→ 拟合残差
```

GBDT 拟合残差本质上是梯度下降在函数空间中的推广——每棵树拟合的是损失函数对当前预测的负梯度。

### Q2：XGBoost 的二阶泰勒展开具体有什么用？

GBDT 只用一阶梯度决定方向：

```
第 t 棵树要拟合的值 = -g_i（负梯度，即残差）
```

XGBoost 同样拟合负梯度，但使用二阶信息来**自适应步长**：

```
叶子 j 的最优输出值 = -Σg_i / (Σh_i + λ)

其中 g_i = 一阶导（梯度）
      h_i = 二阶导（Hessian，Hessian矩阵的主对角线元素）
      λ = 正则化参数
```

二阶导 h_i 反映的是"损失函数在这个点的曲率"。曲率大（h_i 大）→ 损失函数变化快 → 步长应该小一点（分母增大）。曲率小 → 损失函数平坦 → 步长大一点也没关系。

**对比梯度下降中的学习率**：梯度下降全局统一学习率，XGBoost 每个叶子自适应步长。这就是二阶信息的价值。

### Q3：XGBoost 的二阶导和 Adam 的二阶矩有什么区别？

面试中常被混淆。

| | XGBoost 二阶导 | Adam 二阶矩 |
|---|---|---|
| **计算对象** | 损失函数对预测值的 Hessian | 梯度的平方（梯度方差估计） |
| **含义** | 损失函数的曲率 | 梯度的波动程度 |
| **用途** | 自适应步长（叶子值 = -Σg/Σh） | 自适应学习率（lr / √v_t） |
| **层面** | 函数空间优化 | 参数空间优化 |

两者都在做"自适应"，但适应的对象不同：XGBoost 适应的是损失函数的局部曲率，Adam 适应的是参数更新的历史波动。不是同类项。

### Q4：LightGBM 的 Leaf-wise 为什么要压制？

Leaf-wise 每次只分裂增益最大的叶子，树长成"又深又窄"的形状——在增益大的方向拼命往深处钻。这在训练集上拟合极好，但到了测试集 → 过拟合。

代码里两道防线：

```
num_leaves=31  ← 叶子数到 31 就停。2^7=128 的满二叉树，只允许 31 个叶子
max_depth=7    ← 深度到 7 就停，即使叶子数还不满 31
```

两个条件任一满足就停止。num_leaves 是主要约束（压制 leaf-wise 的贪婪天性），max_depth 是兜底防线。

### Q5：GOSS（基于梯度的单边采样）具体怎么做？

1. 把所有样本按梯度绝对值降序排列
2. 保留梯度最大的前 a%（如 top 20%）——这些是模型学得不好的"难样本"，必须留着
3. 从剩余 80%（梯度小的"容易样本"）中随机采样 b%（如 20%）
4. 被采样的小梯度样本，计算信息增益时乘以 (1-a)/b 的放大系数

```
实验对比（LightGBM 论文）：
  传统 GBDT：所有样本全算 → 精度最高但慢
  随机采样：随机丢一半样本 → 精度显著下降
  GOSS：top20% 全保留 + 80% 里抽 20% → 精度损失可忽略，速度大幅提升
```

关键是保留"大梯度样本"——他们是模型最需要学习的内容。丢掉他们，和丢掉关键的知识点一样，模型学不好。

### Q6：CatBoost 的 Ordered Boosting 怎么防止目标泄露？

传统 GBDT 第 t 轮：用全量数据训练 → 算梯度。样本 i 的梯度里包含了样本 i 自己的信息 → 目标泄露。

CatBoost 的 Ordered Boosting：对每个样本 i，只用排列在它之前的数据训练模型，用那个模型算样本 i 的梯度。样本 i 的信息完全不会泄露进自己的梯度。

但不需要训练 N 个模型——对称树结构确保了可以用增量统计高效计算。建第 t 棵树时，沿排列逐步累加前 t-1 棵树的预测值，每步 O(1)。

### Q7：为什么要同时用 XGBoost、LightGBM、CatBoost？

集成学习的核心原则：**成员相关性越低，集成效果越好**。

三个 GBDT 虽然同族，但树结构和优化方向不同。两个成员之间的相关性约 0.7-0.8。加上 RF（完全不同家族，Bagging），相关性进一步降低到 0.3-0.5。

Stacking 中元学习器学到的权重能反映这种差异——RF 在某些样本上和其他 GBDT 意见不同时，元学习器能判断"这次该信谁的"。

### Q8：Voting 的 weights=[2,1,1] 是怎么来的？

基于验证集上 XGBoost 单模型 F1 最高。不是精确搜索的结果，而是一个启发式设置。

更好的做法是用 grid search 搜索 (1~3, 1~2, 1~2) 的组合，在这个项目中大概 9-18 种组合，可以找到更优的权重。但实践中差异通常在 0.5% 以内，[2,1,1] 已经够用。

### Q9：Stacking 中 cv=5 的作用？

如果不用 CV——基模型在全部训练集上训练后用同一份数据预测 → 预测值是"自嗨"的（过拟合后的值）→ 元学习器学到的是噪音。

5 折 CV 确保每个训练样本的预测值来自一个**没见过它**的模型：

```
折1：用折2-5 训练 → 预测折1 → 干净预测
折2：用折1,3-5 训练 → 预测折2 → 干净预测
...
```

拼起来后每个样本的预测都是"无偏"的。元学习器学到的是基模型的真实泛化能力。

### Q10：元学习器为什么用 LogisticRegression？

四个原因：
1. **简单 = 不易过拟合**：第二层只有 4 个特征（4 个基模型的预测），用复杂模型容易在这 4 维上过拟合
2. **可解释**：学到的系数直接反映"每个基模型的权重"
3. **输出概率**：predict_proba 天然支持
4. **线性组合就是 Voting 的推广**：LogisticRegression 的输出 = sigmoid(Σ w_i × p_i + b)，其实就是学出来的 Voting 权重

### Q11：阈值优化为什么要做？默认 0.5 有什么问题？

模型输出的是概率，不是标签。0.5 一刀切是"习惯"不是"科学"。

在 6:1 不平衡的情况下，水军的预测概率天然偏低——真实水军可能只拿到 0.42 的概率，0.5 的线会漏掉他。降低阈值 → 提高 Recall → F1 上升。直到 Precision 的下降抵消了 Recall 的上升 → 这个点就是 F1 最优的阈值。

项目中搜索 0.3~0.7（步长 0.01），通常最优阈值在 0.35~0.45 之间。注意：搜索的是 F1 最优，不是 Accuracy 最优。Accuracy 在不平衡场景会欺骗你——全判正常就能拿到 86% 的 Accuracy，但一个水军没找到。

## 九、高频追问 — BERT 和语义特征

### Q1：BERT 和 Word2Vec 的核心区别？

**Word2Vec**：每个词 → 一个固定的向量，不管上下文。例如"苹果"无论在"吃苹果"还是"苹果手机"中，都是同一个 300 维向量。

**BERT**：每个词 → 根据**整句话的上下文**动态生成向量。同一个"苹果"在不同句子中得到不同的向量。

```
"我喜欢吃苹果"中的"苹果" → 向量接近"水果""食物"区域
"苹果发布了新手机"中的"苹果" → 向量接近"科技""公司"区域
```

这是 BERT 区别 Word2Vec 的根本性突破——它真正做到了"根据上下文理解词义"。

技术上依靠 Transformer 的自注意力机制：每个词的输出向量 = 所有输入词向量的加权和，权重由"谁和谁语义相关"决定。

### Q2：BERT 是怎么训练的？两个预训练任务是什么？

BERT 在海量文本上做**自监督学习**（不需要人工标注），通过两个任务学会理解语言：

**任务1：MLM（Masked Language Model）— 完形填空**

随机遮住 15% 的输入词，让模型猜被遮住的词是什么。关键：模型必须在**看到左右上下文**的情况下才能猜对。

```
输入："这个产品质量 [MASK]，值得购买"
训练目标：猜 [MASK] = "不错"/"很好"（不会是"垃圾"，因为后面是"值得购买"）

训练作用：让模型学会词语的语义、搭配、上下文依赖
```

**任务2：NSP（Next Sentence Prediction）— 判断两句话是否相邻**

给模型两句话，判断它们是否在原文中相邻。

```
句子A："我今天去超市了"
句子B："买了很多水果" → 相邻 → 正例
句子C："明天可能下雨" → 不相关 → 负例

训练作用：让模型理解句子之间的逻辑关系和篇章结构
```

经过这两个任务训练后，BERT 学会了语言的深层表示。这也是为什么 BERT 输出向量能反映语义——因为它通过大量训练已经知道了"意思相近的文本应该有相似的向量表示"。

### Q3：Sentence-Transformers 和原生 BERT 的区别？

原生 BERT 输出每个 token 的向量——一句话 → 多个向量（每个字一个）。做句子比较需要额外处理（如取 [CLS] token 或平均池化）。

Sentence-Transformers = BERT + 池化层 + 针对"句子语义相似度"的微调训练：

- 训练时使用 Siamese Network（孪生网络）结构——两句输入同一个 BERT → 池化 → 两个句子向量 → 算相似度 → 优化"相似句近、不相似句远"
- 输出时：一句话 → 一个 384 维向量（Mean Pooling 合并所有 token 向量）
- 专门优化的语义相似度能力比原生 BERT 更准确

项目中用 MiniLM 版本（L12-v2），384 维（BERT-base 是 768 维）。MiniLM 通过知识蒸馏从大模型压缩得到，速度翻倍但精度几乎不降。

### Q4：BERT 为什么能让 F1 从 0.58 跳到 0.84？

分析提升的三个来源：

**Recall 提升最大（0.53 → 0.86，+33 点）**：BERT 提供了一种全新的语义维度信息。那些"行为看起来正常但内容语义异常"的水军（比如用自然语言写的模板）被大量找到。

**Precision 提升（0.59 → 0.82，+23 点）**：BERT 帮模型更好地区分"真的正常评论"和"假装正常的模板评论"。减少了将正常用户误判为水军的比例。

**AUC 提升（0.87 → 0.96）**：模型的整体区分能力大幅提升。即使不调整阈值，ROC 曲线下的面积也说明模型更强了。

具体来说，BERT 特别擅长检测：① 模板复制水军（语义向量高度重叠）；② 情感操纵水军（异常高的正面/负面情感密度）；③ 不自然表述（机器翻译/生成的不自然中文）。

### Q5：BERT 和手工特征一起用，不会信息冗余吗？

不冗余，它们是**互补**的：

手工特征回答：这个人**怎么**发评论的？（频率、时间、评分模式）——行为维度
BERT 特征回答：这个人**说了什么**？（内容、语义、风格）——内容维度

互补最典型的表现：有些水军行为完全正常（发帖频率低、时间合理、评分中等），但评论内容是 AI 生成的。手工特征看不出任何异常，BERT 却能捕捉到生成文本的结构特点。

反之亦然：有些水军评论内容和正常用户完全一样（复制粘贴真实用户的评论），但行为极度异常（1 分钟发 30 条）。BERT 看到的是正常内容，手工特征却能看到行为异常。

### Q6：为什么选 MiniLM 而不是中文 BERT-wwm 或 RoBERTa？

三个考量优先级：

**速度**：384 维 vs 768 维，推理快 1 倍。项目中 12000 条评论要一次性编码完，MiniLM 几分钟，BERT-base 要十几分钟。面试展示时可以快速复现。

**任务匹配**：paraphrase 系列专门为语义相似度训练——水军检测的核心就是发现"内容高度相似"的评论群。这个任务和 MiniLM 的训练目标天然匹配。

**中英文支持**：multilingual 版本覆盖 50+ 语言，中文表现实测不错（F1 能到 0.84 就证明了）。如果追求极致，可以换中文专用模型（可能再提 1-2 点），但 MiniLM 已经足够证明 BERT 的价值。

## 十、高频追问 — 可解释性（SHAP + LIME）

### Q1：SHAP 的理论基础是什么？

SHAP 基于博弈论的**Shapley 值**，是一种"公平分账"方案。场景：N 个玩家合作赚了钱，怎么分配才公平？Shapley 值给出唯一满足四个公理的分配：

1. **效率性**：所有特征的贡献 + 基准值 = 最终预测值（账分完）
2. **对称性**：两个特征在所有联盟中贡献相同 → SHAP 值相同（公平对待）
3. **虚拟性**：加入任何联盟都不改变结果的玩家 → SHAP 值 = 0（没贡献不拿钱）
4. **可加性**：Shapley 值可以跨模型加和（多个模型的 SHAP 值可以直接相加）

SHAP 把"特征"当作玩家，把"模型预测"当作合作收益，每个特征的 SHAP 值 = 该特征在所有可能的特征子集上的边际贡献的加权平均。

### Q2：SHAP 的 TreeExplainer 为什么那么快？

树模型结构完全透明——不需要采样、不需要扰动。

SHAP 值可以从每棵树直接精确计算：遍历树，在每个节点根据样本走了左/右子树来确定该节点的特征对预测的贡献。时间复杂度 O(TLD²)，T=树数，L=最大叶子数，D=深度。

对于 300 棵树、depth=7、叶子 128 的模型，500 个样本的 SHAP 值几秒算完。KernelExplainer（通用黑箱）同样的计算量需要几百倍的时间。

TreeExplainer 的另一个优势：结果是**精确解**，不是近似——不需要像 KernelExplainer 那样采样估计。

### Q3：LIME 有什么局限性？和 SHAP 怎么配合？

**LIME 的局限性**：

1. **不稳定**：两次运行可能得到不同的结果（随机扰动 + 采样，每次生成的干扰样本不同）
2. **局部性局限**：在这个样本附近是线性的，远一点可能完全不线性。LIME 不描述全局行为
3. **难调参数**：kernel width（邻居范围的半径）不好设，太小 → 扰动样本太少，太大 → 不再"局部"
4. **强相关特征失效**：如果两个特征高度相关，LIME 扰动时可能生成不合理的组合（比如 is_night=1 和 hour=14 同时出现，现实中不可能）

**配合方式**：

```
SHAP（全局）：看整体 → is_night 是最重要的特征
SHAP Waterfall（局部）：看单样本 → 这个样本的预测是怎么来的
LIME（局部验证）：用另一种方法看看是不是得到相似的结论
                 → 如果 SHAP 和 LIME 的重要特征一致 → 结论更可靠
```

### Q4：Beeswarm 图怎么看？有什么信息量？

Beeswarm 在一张图里同时传达了三个维度的信息：

1. **排名**：从上到下按 SHAP 值绝对值均值排序 → 特征重要性排名
2. **方向**：每个点落在正/负轴 → 这个特征在这个样本上是推向水军还是拉向正常
3. **交互**：颜色代表特征值高低 → 红色（高值）在正轴 → "高值推高水军概率"

例如 is_night 这一行：红色点（深夜）集中在正轴（推高水军概率），蓝色点（白天）集中在负轴（推低水军概率）。这完美验证了"深夜发帖 → 更像水军"的假设。

### Q5：为什么选择 XGBoost 做 SHAP 解释而不是其他模型？

XGBoost 在 Voting 中权重最高（[2,1,1]），是"主力模型"。解释主力模型 → 最能代表最终系统的决策逻辑。而且 XGBoost 的树结构用 TreeExplainer 计算最快。

如果面试官追问"那你怎么知道其他模型的决策逻辑是一样的"，可以回答：① LIME 对几个模型都跑一遍，验证它们的重要特征高度一致；② 这说明模型学到的是数据本身的规律，不是某个模型特有的偏好。

## 十一、高频追问 — 项目整体

### Q1：这个项目最大的技术挑战是什么？

最大的挑战不是某个算法调参，而是**"特征决定了模型的上限"这个认知的验证**。

手工特征从 20 个做到 Step 4 的 0.58，方法上已经把 SMOTE、集成、阈值优化都做完了。提升空间已经很小了。真正的突破来自 **BERT 语义特征**的引入——它提供了手工特征完全缺失的"内容维度"信息。

这个过程让我深刻理解：ML 项目的瓶颈往往在特征层面，模型改进的是"逼近上限的能力"，而特征决定了"上限本身"。

### Q2：如果重新做这个项目，会怎么改进？

**数据层面**：
- 增加更多标注样本，特别是"模糊地带"的样本（难以判断是否是水军的评论）
- 引入用户画像特征（注册时间、历史购买记录、IP 地址等）
- 加入评论图片/视频的多模态特征

**模型层面**：
- 用更大的中文 BERT（RoBERTa-wwm-ext）替代 MiniLM → 预期 F1 +1~2%
- 加入时序建模（LSTM/Transformer 捕捉发帖时间序列的规律）→ 水军常在特定时间点集中操作
- 对比学习（SimCSE）让语义表示对水军检测更友好

**工程层面**：
- 做模型量化（INT8）加速 BERT 推理 → 满足在线实时检测需求
- 建立 A/B 测试框架 → 灰度验证模型效果
- 加入模型监控 → 检测特征漂移和模型衰减

**可解释性**：
- 生成面向运营人员的可视化报告 → 提升可解释性的业务价值
- 对误判样本做 case study → 指导下一轮特征工程

### Q3：图特征只有 6 维但信息密度高，怎么验证？

通过特征重要性分析——6 维图特征占 410 维约 1.5%，但在 XGBoost 的特征重要性中占比通常 5-8%，说明它们的信息密度是平均水平的 3-5 倍。而且 AUC 从 0.96→0.976 的提升也证明这 6 维包含了有价值的信息。

### Q4：项目实际部署有哪些考虑？

**延迟**：BERT 编码一条评论约 10-50ms（CPU），加上 XGBoost 推理约 1ms。对于实时评论流（每秒几十条），需要 GPU 加速或使用 ONNX Runtime 做模型优化。

**成本**：BERT 推理需要 GPU（或 CPU 多线程）。如果日处理百万条评论，MiniLM 384 维比 BERT-base 768 维节省一半计算资源。

**阈值策略**：
```
概率 ≥ 0.8  → 高风险 → 自动删除/隐藏
0.6 ≤ 概率 < 0.8 → 中风险 → 人工审核队列
0.4 ≤ 概率 < 0.6 → 低风险 → 标记但不处理
概率 < 0.4 → 正常 → 直接发布
```

**监控**：跟踪特征分布（is_night 在全部评论中的比例是否突变）、模型 A/B 效果（新模型 vs 旧模型的 F1 差异）、水军比例预估（检测到的水军占比是否稳定）。

### Q5：为什么用 F1 而不是 Accuracy 作为主要指标？

在 6:1 不平衡场景下，Accuracy 会严重误导：

```
如果模型全判"正常"：
  Accuracy = 10000/12000 = 83.3% ← 看起来不错！
  Recall（水军）= 0/2000 = 0%   ← 一个水军没找到
  F1 = 0                        ← 暴露真相
```

F1 是 Precision 和 Recall 的调和平均，对两个指标的低值都敏感。一个指标为零 → F1 为零。这迫使模型必须在"找得准"和"找得全"之间取得平衡。

### Q6：Precision 和 Recall 的取舍？什么场景更看重哪个？

**看重 Precision（宁可漏，不能冤）**：
场景：自动封禁 → 封错了 → 用户投诉、体验受损。需要高 Precision。

**看重 Recall（宁可冤，不能漏）**：
场景：初筛 → 人工复核 → 冤枉的可以被人工纠正，漏了就永远漏了。需要高 Recall。

本项目 F1 平衡了两者。通过阈值调整可以偏向任一方。阈值降低 → 多判水军 → Recall 上升、Precision 下降。

### Q7：SHAP 分析发现 is_night 是 Top 1 特征，有什么实际意义？

**模型层面**：验证了初始特征设计的正确性——时间维度确实是水军行为的最大破绽。

**业务层面**：建议平台对深夜时段（0-6点）发布的评论加强审核力度，这是成本低、收益高的精准打击策略。

**后续优化**：可以深挖时间相关特征——不只"是否深夜"，还有"是否在非人类活跃时间"（更精细化的小时段划分）、"发帖时间间隔的均匀程度"（脚本发的→时间间隔接近固定的某个值，而非人类的随机间隔）。

## 十三、常见"坑"和应对

### 面试中可能暴露的弱点和应对

**弱点 1："你的项目 F1 0.84，看起来很普通"**

应对：在电商评论水军检测这个任务上，0.84 是很好的结果。数据有 6:1 不平衡，水军模仿正常用户的能力越来越强。而且重点是**提升幅度**——从 0.11 到 0.84，相对提升超 600%。这证明了技术路线的有效性。

**弱点 2："你用的是 3 年前的技术（XGBoost、BERT）"**

应对：选择技术栈的原则是"适合"而非"最新"。表格数据 + 3000-10000 样本量 → GBDT 比深度学习更合适。而且项目展示了完整的方法论——特征工程→模型选型→可解释性→语义增强，这套方法论在新方法上同样适用。如果我换成最新的 LLM（如 GPT 提取特征），流程是一样的，只是换了一个特征提取器。

**弱点 3："图网络只有 6 维特征，提升也不大"**

应对：维度确实少，但信息密度高——6 维占 1.5% 但贡献 5-8% 的重要性。而且 AUC 从 0.96→0.976 的提升是有意义的——模型排序能力更强，更多水军进了高置信度区间。另外图特征的可解释性好（"这个人在网络中的位置异常"），在业务上是加分项。

**弱点 4："你没做超参数调优"**

应对：项目中通过对比实验选参了（300 vs 500 棵树，lr=0.05 vs 0.03），但没有做系统性的 Grid Search 或贝叶斯优化。原因是：① GBDT 的默认参数通常已经不错，重点在特征质量；② 超参优化的收益（~1-2% F1）远小于特征增强的收益（+26% F1）；③ 如果面试官在意，可以说这也是后续可做的一个方向。

## 十六、模型评价指标详解

### 零、一切指标的基础：混淆矩阵

先把四个基本元素搞清楚：

```
                    真实情况
                  正常      水军
              ┌─────────┬─────────┐
预测    正常  │   TN    │   FN    │
              │ 真阴性   │ 假阴性   │
              │ 正确放过 │ 漏网之鱼 │
              ├─────────┼─────────┤
        水军  │   FP    │   TP    │
              │ 假阳性   │ 真阳性   │
              │ 冤枉好人 │ 正确抓到 │
              └─────────┴─────────┘
```

用具体数字记：

```
测试集 2400 条：2100 正常 + 300 水军

模型判了 350 个水军，2050 个正常

  判水军的 350 个里：260 个真的水军（TP），90 个被冤枉的正常人（FP）
  判正常的 2050 个里：2010 个真的正常（TN），40 个漏掉的水军（FN）

验证：2010 + 90 + 40 + 260 = 2400 ✅
```

**面试画图要点**：先说清 TP/TN/FP/FN 四个格子的含义，所有指标都从这四个数派生。

---

### 一、Accuracy（准确率）

**公式**：

```
Accuracy = (TP + TN) / 总数 = (260 + 2010) / 2400 = 94.6%
```

**翻译**：所有判断中，判对了多少。

**致命的陷阱**：

```
如果模型全判"正常"：
  TP = 0, TN = 2100, FP = 0, FN = 300
  Accuracy = (0 + 2100) / 2400 = 87.5%

  一个水军没抓到，准确率竟然有 87.5%！
  → Accuracy 在不平衡数据上会骗人
```

**面试话术**：Accuracy 适合类别均衡的场景。水军检测 6:1 不平衡，全判正常就有 86%，看 Accuracy 等于没看。所以项目用 F1 和 AUC 做主指标。

---

### 二、Precision（精确率 / 查准率）

**公式**：

```
Precision = TP / (TP + FP) = 260 / (260 + 90) = 74.3%
```

**翻译**：你判为水军的人中，有多少真的是水军？

**直觉**：

```
Precision 高 → "抓得准"
  标记了 10 个水军，9 个真的是 → Precision = 90%
  适用于：自动封禁场景（封错了用户投诉，代价大）

Precision 低 → "冤枉了很多人"
  标记了 10 个水军，只有 3 个是 → Precision = 30%
  抓到的确实不多，但里面混了大量正常用户
```

**影响因素**：阈值越高 → 只抓铁证如山的 → Precision 越高，但 Recall 越低。

---

### 三、Recall（召回率 / 查全率）

**公式**：

```
Recall = TP / (TP + FN) = 260 / (260 + 40) = 86.7%
```

**翻译**：所有真实水军中，你抓到了多少？

**直觉**：

```
Recall 高 → "抓得全"
  300 个水军，抓了 290 个 → Recall = 97%
  适用于：初筛场景（宁可冤几个，不能漏一堆，反正有人工复核兜底）

Recall 低 → "漏了很多"
  300 个水军，只抓了 100 个 → Recall = 33%
  抓到的确实是水军，但大部分水军逍遥法外
```

**影响因素**：阈值越低 → 更多样本被判水军 → Recall 越高，但 Precision 越低。

---

### 四、Precision 和 Recall 的互斥关系（面试必问）

两者天然互斥，提高一个往往牺牲另一个。根本原因：**阈值在左右互搏**。

用同一个模型，不同阈值下的表现：

```
阈值 = 0.7（保守）：
  只抓"铁证" → 抓了 200 个，180 个真的
  Precision = 180/200 = 90%  ↑ 高
  Recall    = 180/300 = 60%  ↓ 低（漏了 120 个）

阈值 = 0.5（默认）：
  抓了 350 个，260 个真的
  Precision = 260/350 = 74%  ← 中间
  Recall    = 260/300 = 87%  ← 中间

阈值 = 0.3（激进）：
  宁可错杀 → 抓了 500 个，290 个真的
  Precision = 290/500 = 58%  ↓ 低（冤了 210 个）
  Recall    = 290/300 = 97%  ↑ 高（只漏了 10 个）
```

**图景**：

```
阈值 ↑（保守）          阈值 ↓（激进）
Precision 高              Precision 低
Recall 低                 Recall 高
"抓得准，漏得多"           "抓得全，冤得多"
```

**面试追问：什么场景更看重哪个？**

| 场景 | 更看重 | 原因 |
|---|---|---|
| 自动封禁 | Precision | 封错了用户会投诉，体验极差 |
| 反欺诈初筛 | Recall | 漏掉真欺诈损失大，冤枉的可以人工纠正 |
| 内容审核 | F1 平衡 | 既要用户体验又要内容安全 |
| 医疗诊断 | Recall | 漏诊比误诊更致命 |

---

### 五、F1-Score

**公式**：

```
F1 = 2 × (Precision × Recall) / (Precision + Recall)
```

这是调和平均（Harmonic Mean），不是算术平均。

**为什么是调和平均？用反例说明：**

| 极端模型 | Precision | Recall | 算术平均 | F1（调和平均） |
|---|---|---|---|---|
| 全判水军 | 0.125 | 1.0 | 0.56 | **0.22** |
| 全判正常 | 0 | 0 | 0 | **0** |

全判水军时 Recall=1.0，算术平均硬生生拉到 0.56，看起来"还行"——但 Precision 只有 0.125，每 8 个标记才有 1 个是真的，完全不可用。F1=0.22 直接暴露了问题。

**调和平均的特性**：对低值更敏感。一个低 → F1 就低。只有 Precision 和 Recall 都高，F1 才高。这正是水军检测需要的。

**算术平均 vs 调和平均的本质**：

```
算术平均：等权重看待
  (0.1 + 0.9) / 2 = 0.5  ← 被高值拉起来了

调和平均：惩罚低值
  2 × (0.1 × 0.9) / (0.1 + 0.9) = 0.18  ← 被低值拖下去了

为什么好：水军检测不能容忍"Precision 极低但 Recall 极高"，
F1 用调和平均天生惩罚这种不平衡。
```

---

### 六、ROC 曲线和 AUC

**Step 1：两个新概念**

```
TPR（True Positive Rate，真正率）= TP/(TP+FN) = Recall
  翻译：所有水军中抓到了多少比例
  越高越好，最大值 1.0

FPR（False Positive Rate，假正率）= FP/(FP+TN)
  翻译：所有正常用户中冤了多少比例
  越低越好，最小值 0.0
```

**Step 2：ROC 曲线是什么**

遍历所有可能的阈值（从 0 到 1，步长 0.01），每个阈值计算一对 (FPR, TPR)，连成线。

```
阈值=1.0（全判正常）：
  → TPR=0, FPR=0 → 点 (0, 0)

阈值=0.8（保守）：
  → 只有铁证才判 → TPR=0.4, FPR=0.01 → 点 (0.01, 0.4)

阈值=0.5（默认）：
  → TPR=0.87, FPR=0.04 → 点 (0.04, 0.87)

阈值=0.3（激进）：
  → TPR=0.97, FPR=0.10 → 点 (0.10, 0.97)

阈值=0.0（全判水军）：
  → TPR=1.0, FPR=1.0 → 点 (1, 1)
```

连线后：

```
TPR ↑
1.0│                       ●(0.04,0.87) ← 默认阈值
   │                  ╱╱
0.8│              ●──╱
   │          ╱╱╱
0.5│      ╱╱╱
   │   ╱╱
0.0│╱╱
   └──────────────────────────→ FPR
   0.0                    1.0
```

**好模型**：曲线贴近左上角——FPR 很小时 TPR 已经很高。意思是"几乎不冤枉正常人，就能抓到大部分水军"。

**随机猜测**：对角线 y=x。每冤枉一个正常人，才抓到一个水军——效率等同抛硬币。

**差模型**：对角线下方——比随机还差（反向预测，取反即可）。

**Step 3：AUC 是什么**

**AUC = ROC 曲线下的面积（Area Under the Curve）。**

```
AUC = 1.0 → 完美：存在某个阈值，TPR=1 且 FPR=0
AUC = 0.976 → 水军检测项目水平：极强
AUC = 0.9  → 优秀
AUC = 0.8  → 良好
AUC = 0.7  → 一般
AUC = 0.5  → 随机猜测，废的
AUC < 0.5  → 比随机还差，反向预测
```

**AUC 最直观的理解（面试金句）**：

> 随机抽一个水军和一个正常用户，比较模型给他们的预测概率。模型给水军更高概率的概率 = AUC。

```
AUC = 0.976 → 随机抽一对，97.6% 的情况下水军的预测概率高于正常
             → 模型的排序几乎完美
```

**为什么 AUC 不受不平衡影响？**

AUC 只看**排序**，不看绝对值。一万个正常用户和一千个水军——AUC 关心的是"是否每个水军的得分都高于正常用户"，而不是"绝对值是否超过 0.5"。因此不管比例是 1:1 还是 100:1，AUC 的理论范围不变。

### 七、F1 和 AUC 的对比（面试重点）

| | F1 | AUC |
|---|---|---|
| **依赖阈值** | 依赖（一个阈值一个 F1） | **不依赖**（遍历所有阈值） |
| **衡量什么** | 在一个特定决策点的好坏 | 模型的**排序能力**（整体区分力） |
| **适合场景** | 需要实际决策（上线部署） | 评估模型本身的能力 |
| **不平衡敏感性** | 调和平均自带平衡 | 完全不敏感（只看排序） |
| **变化时说明什么** | 阈值变了或模型变了 | 模型的本质区分力变了 |

**项目中 Step 7 的典型现象：F1 持平，AUC 提升**

```
加图特征前：
  水军平均概率 0.72，正常平均概率 0.18
  F1=0.84，AUC=0.96

加图特征后：
  水军平均概率 0.91，正常平均概率 0.07
  F1=0.84（阈值 0.5 下被判对/错的人数差不多），AUC=0.976

含义：
  阈值 0.5 下的分类结果没大变 → F1 持平
  水军和正常的分得更开了 → AUC 提升
  模型信心更足了 → 可以放心把高置信度样本自动处理
```

### 八、Precision-Recall 曲线（不平衡场景的重要补充）

ROC 在不平衡场景下会"过于乐观"：

```
全判水军 → FPR = 冤枉的正常/所有正常 → 100/10000 = 1%
        → TPR = 抓到水军/所有水军 → 1000/1000 = 100%
        → ROC 上这个点：(0.01, 1.0) ← 几乎完美！
        → 但实实在在冤了 100 个正常用户！

ROC 的问题：FPR 的分母是所有正常（很大），
冤枉几百人 FPR 也才百分之几 → ROC 仍然好看
```

**PR 曲线**：纵轴 Precision，横轴 Recall。

```
全判水军 → Precision = 1000/(1000+100) = 91%
        → Recall    = 1000/1000 = 100%
        → PR 曲线上：(1.0, 0.91)

冤枉越多 → Precision 越低 → PR 曲线陡降
→ PR 对"冤枉了多少人"更敏感，更能反映不平衡场景的真实表现
```

**结论**：类别均衡 → ROC；类别不平衡 → 同时看 ROC 和 PR，PR 更能暴露问题。

项目中用 PR 曲线来优化阈值：

```python
precision, recall, thresholds = precision_recall_curve(y_true, y_proba)
f1_scores = 2 * (precision * recall) / (precision + recall + 1e-10)
best_idx = np.argmax(f1_scores)
best_threshold = thresholds[best_idx]
```

```
  PR 曲线  → Precision vs Recall → 不平衡场景更真实
              项目用它来找最优阈值
```
